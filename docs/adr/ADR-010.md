# ADR-010: Storage Layout (Physical Artifact Store)

| Field     | Value                          |
|-----------|--------------------------------|
| Status    | Superseded by ADR-017          |
| Date      | 2026-08-19                     |
| Context   | See below                      |
| Decision  | Consolidated into ADR-017 D2   |

## Context

ADR-010 was reserved in the ADR roadmap as "Storage Layout (SQLite indexing /
Filesystem binary artifact structure)" and was referenced from
`PROJECT_SUMMARY.md` and `index.md` under "Storage & Persistence Layer
(ADR-010 pending)". No dedicated ADR-010 file had been written; the layout
lived only in `docs/storage/architecture.md`.

## Decision

The physical storage-layout decision has been consolidated into **ADR-017
(2026-08-19), decision D2**, which fixes:

- the single user-data root `~/.pmbrs-private` (D1);
- the **raw** layer as one JSON artifact per file (the currently-shipped shape
  written by `scripts/pmbrs_host_sync_ingest.py`);
- the derived / aligned / feature / embedding **target** layer as JSONL +
  SQLite (`events.db`), deferred until the `StorageAdapter` protocol
  (`docs/module-contracts.md`) is implemented;
- the authoritative directory tree, now captured in
  `docs/storage/architecture.md`.

This ADR is therefore **superseded** rather than re-implemented, to avoid two
records encoding the same layout. `docs/storage/architecture.md` (updated
2026-08-19) is the canonical layout reference.

## Consequences

### Positive

- One canonical record for the layout (ADR-017 D2 + `storage/architecture.md`);
  no duplicate ADR.
- The roadmap entry is now closed (`PROJECT_SUMMARY.md`, `index.md` updated).

### Negative

- Readers looking for a standalone ADR-010 decision must follow the pointer to
  ADR-017 D2.

### Neutral / Trade-offs

- **ADR-001 (Storage Backend)** remains the one open storage ADR; it closes
  when the `StorageAdapter` protocol is implemented and the JSONL + SQLite
  target is built.
